# 场景:Projects 检索(corpus/01-projects/)

> 用户问"那个 XX 系统怎么做的 / 上次某客户的方案 / XX 项目第 N 章" — 锚在**具体项目**上的检索。

---

## 默认 scope

`corpus/01-projects/` 下所有项目子目录及其 5 标准子目录(`01-方案 / 02-章节 / 03-纪要 / 04-调研 / 05-附图`)+ `99-其他`。

**`04-archives/` 不在默认 scope**;用户明示"已交付 / 归档" 时再加入。

---

## 检索词层级偏好

第 1 轮检索词起点粒度建议 **主题词 + 项目锚**:

- 项目名 / 客户名是**最强收窄锚**,任何能提到的尽量带上(单点定位 / 决策溯源时尤其有效)
- 主题词:数据安全 / 数据库选型 / 部署架构 / 接口规范 等
- 文件名带 `方案-` / `章节-` / `纪要-` / `调研-` 前缀,**配合前缀可做二档过滤**(如 `rg -A 5 "数据安全" -g "章节-*.md"`)

收窄方向:项目主题 → 子模块名 → 字段词(同 CLAUDE.md 6b 反向回退)
扩展方向:换业务/技术同义词;不轻易跳出"项目素材"语境

---

## frontmatter 二档过滤

v0.2 ingest 注入了 4 字段 frontmatter(type / date / project / tags),在以下场景特别有用:

- 用户问"找方案"时,可加 `rg -A 5 "type: 方案"` 二档过滤,精度提升明显
- 用户问"某项目某时间的事",可加 `rg "project: <项目名>"` + `rg "date: 2024"` 联合过滤
- LLM 自行判断什么时候需要 frontmatter 过滤,**不强制**;命中过多再叠加

---

## 4 行为对应的整合方式提醒

(注:行为识别在 CLAUDE.md 第 2.0 节"步骤 0"已完成,本节是 scope-specific 提醒)

- **单点定位**:项目内多个版本时,优先 frontmatter `date` 最新的;若 stub 与正文都命中,优先正文 .md
- **盘点**:跨项目盘点要按 `project` 分组输出,每项目 1 段;若用户问的是"项目内盘点",按 5 子目录分类输出
- **决策溯源**:优先看 `03-纪要/` 与 `01-方案/` 中"选型 / 对比 / 决策"小节;附引用必须含项目名 + 日期
- **模糊探索**:项目根目录的 `99-其他/` 与 `01-方案/` 优先呈现 3-5 个候选,简短摘要,让用户挑

---

## 跨场景边界

projects 检索最常见的跨界:

- **从 project 跨到 resources**:"那个项目用了什么国标" → 先在 projects 找引用,再到 `03-resources/国标行标/` 找原文
- **从 project 跨到 areas**:"这个项目复用了什么方法论" → 先在 projects 找引用,再到 `02-areas/技术方法论/` 找方法论原文
- **从 project 跨到 archives**:"已交付的同类项目怎么做的" → 用户明示后扩 scope 到 `04-archives/`

跨界在 agent loop 内自动扩,不切换 prompts。

---

## L3 stub 兜底关注字段

L1/L2/L2.5 均无命中、降级到 L3 stub 元数据扫描时,本场景重点关注:

- `frontmatter.project` / `frontmatter.date`(项目锚 + 时间)
- `关键词`(从文件名拆出的主题词)
- `源路径`(原文件位置,建议用户打开)

L3 stub 命中的答案必须明示"原文件未入库正文,仅基于 stub 元数据指向"。
