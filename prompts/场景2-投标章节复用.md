# 场景 2:投标技术章节复用

> 当用户在写技术标某一章时想看"以前同类章节怎么写"——找结构、找措辞、找应答套路。

---

## 素材形态

`corpus/02-投标章节/` 下主要是:

- 历史投标书的技术章节(系统架构、数据安全、运维支撑、培训方案 等)
- 评分点应答(针对招标文件中具体评分项的撰写)
- 商务部分模板(资质、案例、人员)

**注意**:技术标章节通常很长(单章数千字),命中行后必须读上下文才能判断是否真贴合。不要只看一行就下结论。

---

## 检索词层级偏好(agent loop 起点粒度)

本场景目标是"找同类章节的结构与措辞",**首选章节/小节名(中等粒度)**:

- 第 1 轮检索词以章节标题词 / 评分点关键词 / 标准化条款名为起点(如"系统架构"、"数据安全"、"运维支撑"、"培训方案")
- 命中过多时,沿"章节名 → 小节名 → 关键论点词"方向收窄
- 命中 0 时,沿"近义章节名 / 行业标准条款别称"方向扩展

---

## 检索关注点

用户来这个场景**关心的是结构和措辞,不是具体内容**:

1. **章节大纲**:同类章节通常如何组织(几个一级标题、什么顺序)
2. **关键论述要点**:必谈的几个点(比如"系统架构"必谈分层、技术选型、扩展性)
3. **可直接复用的措辞**:行业套路话术、标准化表达
4. **评分点应答套路**:招标文件 → 应答原文的对应方式

---

## 输出格式

```
找到 N 份历史投标书包含同类章节:

【章节大纲对比】
- A 项目(2024,XX 局):一级目录 1.1-1.5 分别为... [引用]
- B 项目(2023,YY 厅):一级目录 1.1-1.6 分别为... [引用]

【关键论述要点(综合多份)】
1. 必谈:XX(几乎所有标书都有)
2. 多谈:YY(超过半数)
3. 特色谈法:ZZ(某项目独有,可借鉴)

【可直接复用的措辞片段】
- "本系统采用 XX 架构,具备 XX 能力" [来自项目 A,corpus/02-投标章节/A项目-技术标-第3章.md:120-128]
- (列 3-5 条即可,不要堆砌)
```

---

## 特殊注意

- 不同项目的同类章节,详略差异巨大。**简单标注每份的字数级别**(2K 字 vs 8K 字),帮助用户判断详略要求
- 如果命中的章节明显是"复制粘贴前一份"的痕迹(常见于同一岗位连续投标),提醒用户避免重复
- 评分点应答有强格式要求(逐条对应、加粗关键词),提醒用户参考时保留这种格式

---

## L3 stub 兜底关注字段

L1/L2 均无命中、降级到 L3 stub 元数据扫描时,本场景重点关注 stub 文件的下列字段:

- `关键词`(从文件名拆出的章节名 / 标段类型 / 招标方类别)
- `日期`(标书时间,投标章节随政策/标准更新,旧标书参考价值衰减快)
- `源路径`(原投标文件位置,后续整段章节复用必须打开原文件)

answer 中如基于 L3 stub,必须明示"原文件未入库正文,仅基于 stub 元数据指向,建议打开原文件以查看完整章节结构"。
