# 场景:Resources 检索(corpus/03-resources/)

> 用户问"国标 / 行标 / 行业研究 / 培训资料 / 竞品分析" — 锚在**外部权威发布的参考资料**上的检索,只参考不维护。

---

## 默认 scope

`corpus/03-resources/` 下所有参考资料子目录:

- `国标行标/` — 国家标准 / 行业标准 / 地方标准
- `行业研究/` — 行业研究报告 / 趋势分析
- `竞品资料/` — 友商方案 / 竞品分析
- `培训与调研/` — 培训资料 / 行业调研报告

---

## 检索词层级偏好

第 1 轮检索词起点粒度建议 **标准编号 + 字段词**:

- 国标 / 行标类:**标准编号是最强锚**(如 `GB/T 35958` / `CJ/T 469`),编号 → 章节号 → 字段词三级收窄
- 行业研究类:研究主题词 + 年份(年份在 resources 类素材中是高价值锚)
- 培训 / 竞品类:培训主题 + 讲师名 / 产品名
- 命中 0 时,沿标准的"上位主题词 / 行业大类"扩展;不轻易扩到无关业务领域

---

## frontmatter 二档过滤

- `frontmatter.project` 在 resources 类素材上**必为 null**(ingest PARA 协议约定)
- 资源类常带 `frontmatter.tags = [行业, 主题词, 国标/培训/...]`,标签是 resources 的核心元数据
- 用户问"国标"时可加 `rg "type: 国标"`;问"培训"时加 `rg "type: 培训"`
- 同一标准多个版本时,按 `frontmatter.date` 排序优先最新

---

## 4 行为对应的整合方式提醒

- **单点定位**:标准条款 / 字段定义类单点定位,必须**逐字引用**原文(不要复述),引用行号精确到段
- **盘点**:盘点 resources 时按子目录分类(国标行标 / 行业研究 / 竞品资料 / 培训与调研),不要混排;同一标准多版本要全列(按时间倒序)
- **决策溯源**:resources 通常**不承载决策溯源**(它是参考依据,不是决策记录);若用户在 resources 找"为什么",提醒"该问题应在 projects 或 areas 找决策记录,resources 仅提供参考依据"
- **模糊探索**:resources 模糊探索给 3-5 个同主题标准 / 研究报告候选,带标准编号 + 发布年 + 字数

---

## 跨场景边界

resources 检索最常见的跨界:

- **从 resources 跨到 projects**:"哪个项目引用了这个国标 / 标准" → 用标准编号回查 projects
- **从 resources 跨到 areas**:"哪个方法论引用了这份行业研究" → 用研究标题回查 areas
- **resources 与 archives 几乎不交叉** — resources 是外部权威发布,与项目归档无关

---

## L3 stub 兜底关注字段

L1/L2/L2.5 均无命中、降级到 L3 stub 元数据扫描时,resources 场景重点关注:

- `frontmatter.tags`(行业 / 主题大类 / 标准类别)
- `frontmatter.date`(标准 / 研究的发布年 — resources 类时间敏感,过时标准参考价值衰减)
- `关键词`(从文件名拆出的标准编号 / 主题词)

L3 stub 命中时,answer 必须明示"原文件未入库正文,**严禁基于 stub 元数据复述标准条款 / 研究数据**;建议打开原文件查看完整条文"。本场景的 stub 禁令力度**与场景-projects 相同**(标准条文一字之差结论可能完全相反)。
