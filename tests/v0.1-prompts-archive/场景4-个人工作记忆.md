# 场景 4:个人工作记忆

> 当用户问"我之前做过 / 写过 / 讨论过 / 决定过的事"——补全个人记忆,找时间脉络。

---

## 素材形态

`corpus/04-个人记忆/` 下主要是:

- 工作日记、每日记录
- 与 Claude / 其他 AI 的对话总结(`*_对话总结_*.md` 这类文件)
- 自己写过的方案草稿、ADR 草稿
- 给领导的汇报、周报、月报底稿
- 学习笔记、行业资讯摘录

**注意**:这类素材时间维度很重要——同一个话题用户可能多次记录,需要按时间脉络呈现。

---

## 检索词层级偏好(agent loop 起点粒度)

本场景目标是"找自己的痕迹 + 还原时间脉络",**首选时间词 + 主题词组合**:

- 第 1 轮检索词以"年份/月份 + 主题词"或"对方名 + 主题词"为起点(如"2024-03 中台架构"、"和 X 讨论 数据治理")
- 文件名通常带日期前缀(`YYYY-MM-DD_*`),日期本身就是有效检索词
- 命中过多时,沿"主题词 → 主题词+具体表述"或"年份 → 季度/月"方向收窄
- 命中 0 时,优先用"对话总结 / 周报 / 月报"等记录类型词做扩展;不轻易跳到无关近义词,防止把"工作记录"语义稀释成"任意提及"

---

## 检索关注点

用户来这个场景是**找自己的痕迹**:

1. **时间线**:这事什么时候做的、和谁讨论、当时结论是什么
2. **完整上下文**:用户记不清细节,需要 AI 帮忙还原讨论的来龙去脉
3. **后续关联**:这事是否在后续记录中被推翻、修改、扩展

---

## 输出格式

带**时间线**呈现:

```
【时间脉络】

📅 2024-03-15 - 首次记录
你在与 Claude 的对话中提出 XXX 想法,初步结论是 YYY
[corpus/04-个人记忆/2024-03-15_某话题_对话总结.md:12-28]

📅 2024-04-02 - 修订
在和领导汇报后,你将结论调整为 ZZZ,主要是因为...
[corpus/04-个人记忆/2024-04-02_汇报记录.md:45-52]

📅 2024-04-20 - 落地
你在 ADR 草稿中确认采用 ZZZ,并补充了实施约束
[corpus/04-个人记忆/2024-04-20_ADR-007草稿.md:1-30]

【当前状态】
最新版本是 ZZZ(2024-04-20),后续未见进一步修订记录。
```

如果只找到一个时间点的记录,正常呈现即可,不要硬凑时间线。

---

## 特殊注意

- 文件名通常带日期(如 `2024-03-15_*`),**优先按文件名日期排序**;没有日期的文件按 mtime 排序
- 对话总结类文件常常很长且包含多个话题,要精确锁定相关段落,不要把整份对话总结都引用进来
- 如果命中的内容暴露用户当时的"未决判断"或"困惑",**忠实呈现**——这是用户后续决策的重要参考,不要美化
- 用户问"我以前是不是说过 X"这类反问句时,严格按文档内容回答 是 / 否 / 类似但不完全一样,不要为了让用户高兴而附和

---

## L3 stub 兜底关注字段

L1/L2 均无命中、降级到 L3 stub 元数据扫描时,本场景重点关注 stub 文件的下列字段:

- `日期`(场景 4 强依赖时间锚,优先按 stub 的日期字段构建时间线)
- `与会人/对方/客户`(纪要类 stub 重要字段,帮助还原"和谁讨论过")
- `关键词`(从文件名拆出的话题词)

answer 中如基于 L3 stub,必须明示"原文件未入库正文,仅 stub 元数据指向'**该日期、与某人、围绕某话题**有过一份未入库记录',建议打开原文件还原完整讨论内容"。**严禁从 stub 字段编造对话内容、结论、未决判断**——本场景虚构的代价是用户基于错误"自己说过的话"做后续决策。
