### 关键事实快照

1. **markitdown 与 mammoth 依赖**:阶段 2 开始时全局 Python 未装 markitdown,经用户确认后 `pip install --user markitdown==0.1.5` 加 `markitdown[docx]`(后者补 mammoth)。reportlab 装上用于 test_src 的 PDF 合成。requirements.txt 未改(只是补装,默认行为已经声明)。
2. **test_src 路径坑**:bash 的 `/tmp` 在 git-bash 下映射到 `%TEMP%`(`C:\Users\...\AppData\Local\Temp`),但 Python 源码字符串里的 `/tmp/` 解析为 `C:\tmp\`。两次 mkdir / cp 后通过把文件从 `C:\tmp\` mv 到 bash 看到的 `/tmp/` 解决。**这条坑值得在阶段 6 docs 更新时记一笔**(防后续测试踩同样坑)。
3. **docx 合成内容 G18 触发**:LLM 合成的 docx 文本短(每个 200-300 字符),density < 1%,全部走 G18 stub 路径。frontmatter 注入到 .stub.md。**4 条 G18 不是失败,是 density 阈值正常工作**。2 个 PDF(reportlab 多页)走 G16 三件共存,.md 正文产生,frontmatter 也注入 .md。
4. **CLAUDE.md 节号重排**:阶段 2 新增 `第 6 节 PARA 路由协议` + `5.6.3 子段`。原 "## 6. 检索词生成示例库" → "## 7. 检索词生成示例库","## 7. 本文件版本管理" → "## 8. 本文件版本管理"。当前节号:1 / 2 / 2.5 / 3 / 3.5 / 4 / 5 / 5.5 / 5.6 / 6 / 7 / 8。
5. **markitdown 0.1.5 ResourceWarning**:每次跑都会输出一行 urllib3/chardet 版本不匹配警告,功能不受影响。如阶段 6 装 .venv 时升级 markitdown 可消除。
