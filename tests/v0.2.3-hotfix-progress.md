## Codex 测试仓库反馈 → v0.2.3 修复对应

### v0.2.3 5th-1: TEXT_EXTS 扩展(commit `d3c16e8`)

**问题**:Codex 在测试仓库真实素材入库时遇到 `.py / .csv / .geojson / .xml / .cpg / .prj / .meta / .tfw` 这类纯文本文件被 `ERROR_UNSUPPORTED_EXT` 拒。

**修复**:`TEXT_EXTS` 扩展 8 个新扩展名,按原文 `shutil.copy2` 入库即被 ripgrep 检索;不调 markitdown。

**风险评估**:无 — TEXT_EXTS 走 cp 不调 markitdown,扩展安全。`.xml` 与 `.docx`(zip 内 xml)无冲突,因 `.docx` 优先匹配 `BINARY_EXTS`。

**验收**:`assert ext in TEXT_EXTS` 单测 + 真实 ingest 时观察 `INGESTED_TEXT` 落地。

### v0.2.3 5th-2: IMAGE_EXTS 扩展(commit `48d13b3`)

**问题**:`.tif / .tiff` 被 `ERROR_UNSUPPORTED_EXT` 拒。

**修复**:`IMAGE_EXTS` 加 `.tif / .tiff`,走现有 V_PENDING_IMAGE 路径 A,Claude Code 内置 vision 能力可识别。

**风险评估**:无 — 扩展现有 vision 路径 A。

### v0.2.3 5th-3: `MARKITDOWN_FAILED_STUB` 降级路径(commit `e63c3e4`)

**问题**:Codex 在测试仓库遇到 29 个 markitdown 转换失败的 `.docx/.xlsx`(用户的 markitdown 缺 `[docx]` extra)。v0.2.2 行为是 `ERROR_MARKITDOWN_FAILED` → 单 item 不入库 + log 报错 = **失败丢文件**。

**修复**:加 `MARKITDOWN_FAILED_STUB` rule_id + `make_stub` 分支 + `process_file_with_explicit_target` markitdown except 分支改为"源文件 cp + stub + frontmatter 注入"(沿用 `STUB_ONLY_ODF_NO_CONVERTER` 同款降级语义)。

**ODF 类专属降级保留不动**,优先匹配。

**设计语义变更**:

| 维度 | v0.2.2 | v0.2.3 |
|---|---|---|
| markitdown 失败 | `ERROR_MARKITDOWN_FAILED` 单 item 不入库 + log 报错 | `STUB_ONLY_MARKITDOWN_FAILED` 源 + stub + 可恢复 |
| 可见性 | exit code(用户可能不看 log) | stub status 字段写明"markitdown 转换失败" |
| 重入 | 装齐依赖后,user mtime 不变 → 增量跳过 | `is_already_ingested` 看 `action.startswith("ERROR_")` 触发重入 → 自动新降级路径 |

**风险**:**失败可能被淹没?** stub status 字段写明"markitdown 转换失败,已复制源文件",LLM 检索时禁令仍要求"建议打开源文件查看",**不会推断未解析正文**。可见性通过 stub 内容维持,不依赖 exit code。

### v0.2.3 5th-4: `UNSUPPORTED_COPY_STUB` 降级路径(commit `2773f22`)

**问题**:Codex 在测试仓库遇到 `.shp/.dbf/.shx/.qix/.zip/.fcs/.ovr` 等暂不支持解析的中小文件。v0.2.2 行为是 `ERROR_UNSUPPORTED_EXT` → 不入库 = **GIS 兜底文件丢**。

**修复**:加 `UNSUPPORTED_COPY_STUB` rule_id + `make_stub` 分支 + `process_file` 最后 fallback 改为"源文件 cp + stub + frontmatter 注入"。

**跟 README §5.1 "shp 不在检索范围"原则一致** — stub 不参与正文检索,只标记文件存在;未来若加专用解析器(GDAL 读 .shp / .dbf),重跑 ingest → 重入正文。

## smoke_test 扩充 10/10 → 12/12(commit `6fe305d`)

### 新增 assert

- **[11/12] markitdown_failed → MARKITDOWN_FAILED_STUB**:**函数级验证**(非 subprocess)
- **[12/12] unsupported_ext → UNSUPPORTED_COPY_STUB**:subprocess 端到端

### [11/12] 为什么改函数级

实测发现 **markitdown 0.1.5 对所有坏 binary 都极度容错 fallback 到 plain text**:

| fixture | markitdown 行为 |
|---|---|
| `b"not real docx" * 4` 标 .docx | 不抛异常,fallback 成 plain text → char_count=92 → G16 INGESTED_MD |
| `b"not real xlsx" * 4` 标 .xlsx | 同上,char_count=92 |
| `b"not real pdf" * 4` 标 .pdf | 同上,char_count=88 |

**结论**:无法用 subprocess + 坏 fixture 端到端模拟真实失败。所以 [11/12] 改为 **直接 import ingest 模块 + 调函数**验证:

- `make_stub(..., "MARKITDOWN_FAILED_STUB", ...)` 输出含"markitdown 转换失败" / "已复制源文件" / "未入库正文"
- `REQUIRED_FIELDS_SCHEMA` 仍 6 字段(防回退)

**端到端验证补丁**:由 Hugin 在 manual 模拟 markitdown 缺依赖场景(pip uninstall mammoth + 跑 ingest)验证;本 progress.md 落表为待办。
