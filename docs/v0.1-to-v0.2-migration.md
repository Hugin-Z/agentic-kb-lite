# v0.1.0 → v0.2.0 迁移指南

> 本指南面向从 v0.1.0 升级到 v0.2.0 的用户。v0.2.0 是显著重构(corpus 结构 / ingest 范式 / 检索体系全换),迁移需按本指南顺序执行。

---

## 1. 重大变更速览

| 维度 | v0.1.0 | v0.2.0 |
|---|---|---|
| **corpus 结构** | 扁平 4 目录(`01-历史方案 / 02-投标章节 / 03-技术决策 / 04-个人记忆`) | **PARA 四层**(`01-projects / 02-areas / 03-resources / 04-archives`);projects 内部 5 固定子目录(`01-方案 / 02-章节 / 03-纪要 / 04-调研 / 05-附图`)+ `99-其他` |
| **ingest 范式** | `python ingest.py <path>` 单命令 + `path_map.yaml` 规则匹配路由 | `python ingest.py scan-only <src>` + `execute-plan <plan>` 两步;**AI 在 agent loop 中读 routing_request.json + 应用 CLAUDE.md §6 PARA 路由协议产出 plan**;path_map.yaml 退化为语义说明 + hints + explicit_mappings 兜底 |
| **场景体系** | 4 个素材类型场景(历史方案 / 投标章节 / 技术决策 / 个人记忆) | **scope × behavior 双轴**:scope = PARA(projects/areas/resources/跨corpus);behavior = 4 类行为(单点定位 / 盘点 / 决策溯源 / 模糊探索) |
| **prompts/** | 4 个场景文件(`场景1-历史方案查询.md` 等) | 4 个 PARA scope 文件(`场景-projects.md / 场景-areas.md / 场景-resources.md / 场景-跨corpus盘点.md`);v0.1 备份在 `tests/v0.1-prompts-archive/` |
| **新格式支持** | docx / pdf / pptx / xlsx + 纯图像 + 视频 | 上述 + **docx 嵌入图三闸过滤 + vision 注入主 .md** + **docx 嵌入表 python-docx 抽取补段** + **vsdx LibreOffice 转 PDF**(LibreOffice 不可用时降级 stub)+ **odf 兼容**(markitdown 0.1.5 不支持时降级 stub) |
| **frontmatter** | 无 | ingest 时自动给 .md / .stub.md 注入 4 字段 frontmatter(type / date / project / tags);resources 类 project=null |
| **search.py** | `--scene 01/02/03/04/all` | `--scope projects/areas/resources/archives/all`(`all` 默认不含 archives)+ 新增 `--project <名>` 限定单项目 |
| **CLAUDE.md** | §1 4 场景定位 + §2 三级降级 → 四级降级 + ... + §5 4 场景路由表 | §1 PARA 双轴定位 + **§2.0 步骤 0 检索行为识别(新)** + §2 状态段 schema 加 v0.2 3 字段 + §2.5.2 路径 A 表新增 docx 嵌入图 / vsdx 行 + §5 PARA 关键词路由表 + §5.6.3 归档候选(新)+ **§6 PARA 路由协议(新,98 行)** |

## 2. 迁移步骤

### 2.1 备份(双保险)

```bash
git checkout main
git pull
git tag v0.1.0-pre-v02-migration       # git 层
git push origin v0.1.0-pre-v02-migration

# 文件副本(防 .gitignore 排除的本地素材丢失)
cp -r agentic-kb-lite agentic-kb-lite.backup-$(date +%Y%m%d)
```

### 2.2 拉 v0.2.0

```bash
git fetch origin
git checkout v0.2.0
```

### 2.3 跑迁移脚本(corpus 重组)

```bash
# dry-run 先看
python scripts/migrate_v01_to_v02.py

# 审过后再 commit(交互确认)
python scripts/migrate_v01_to_v02.py --commit
```

**v0.1 → v0.2 bucket 固定对应**:

- `01-历史方案/` → `01-projects/`
- `02-投标章节/` → `02-areas/投标章节模板/`
- `03-技术决策/` → `02-areas/技术方法论/`
- `04-个人记忆/` → `03-resources/培训与调研/`

**注意**:这个对应是**机械迁移**,确保不破坏文件。**真实场景下你可能需要进一步手动整理** — 比如 `01-历史方案/` 下的"标准/规范"子目录应该脱钩到 `03-resources/国标行标/`,但脚本不会自动做这件事。脚本只把 4 个 v0.1 bucket 的内容平移到对应 v0.2 bucket。后续整理走 v0.2 ingest 流程(AI 语义路由)。

### 2.4 重跑 ingest(首次会全量重入)

```bash
# v0.5 增量机制下首次跑会触发一次性全量重入(by design)
# 这是因为 v0.1 ingest_log.jsonl 缺 src_mtime 字段,v0.5 判 mtime 不等 → 重入
python scripts/ingest.py scan-only D:/我的项目资料

# AI 在对话层读 routing_request.json + 产出 routing_plan.json + 你 review 后:
python scripts/ingest.py execute-plan logs/routing_plan.json
```

### 2.5 跑评估场景验证

```bash
# 11 个旧 fixture(E1-E7 + V1-V4)在 v0.2 prompts 下应继续 PASS
# 6 个新 fixture(E8-E10 + V5-V7)是 v0.2 新增,详见 tests/查询记录.md
ls corpus/.fixtures/
```

详细评估走 [tests/查询记录.md](../tests/查询记录.md) 各场景的"本次回归结果"段落。

## 3. 不兼容点(需要用户手动处理)

### 3.1 path_map.yaml schema 不兼容

v0.1 的 `path_mappings:` 显式 source → target 字段在 v0.2 **已废弃**(AI 自动路由)。如果你的 v0.1 `path_map.yaml` 有大量 `path_mappings:` 条目,**不会自动迁移**;v0.2 的 path_map.yaml 是新 schema(`buckets` 语义说明 + `hint_subdir_keywords` + `explicit_mappings` 兜底)。

**迁移建议**:看 v0.1 path_mappings 里哪几条是"AI 不会自动判对的边界 case",把它们移到 v0.2 的 `explicit_mappings` 字段。其余条目废弃。

### 3.2 prompts/ 不兼容

v0.1 4 个 prompts 文件已删除并备份到 `tests/v0.1-prompts-archive/`。如果你有自定义修改的 v0.1 prompts,需要**手动移植**到 v0.2 的对应 4 个新 prompts:

- `场景1-历史方案查询.md` 内容 → `场景-projects.md`(项目类素材的检索词偏好 / 整合方式提醒部分)
- `场景2-投标章节复用.md` 内容 → `场景-areas.md`(投标章节模板对应 `02-areas/投标章节模板/`)
- `场景3-技术决策溯源.md` 内容 → `场景-areas.md`(技术方法论)+ `场景-projects.md`(项目内决策)
- `场景4-个人工作记忆.md` 内容 → `场景-resources.md`(培训与调研)

### 3.3 ingest.py 单命令入口不兼容

v0.1 的 `python ingest.py <path>` **单命令入口**在 v0.2 已替换为 **`scan-only` + `execute-plan` 两步**。你不能直接调旧命令了 — **必须通过 AI 编程助手在 agent loop 中产出 routing_plan.json**。

**手动跑(不推荐)**:你可以手写一个 routing_plan.json(schema 见 [docs/v0.2-plan.md §5.3 步骤 2.3](v0.2-plan.md)),但失去了 AI 语义路由的优势。**推荐做法**:让 AI 跑。

### 3.4 ingest_log.jsonl 全量重入(by design)

v0.1 的 `logs/ingest_log.jsonl` 记录无 `src_mtime` 字段,v0.5 / v0.2.0 的增量机制会判 mtime 不等 **触发一次性全量重入**(等同首次跑全量)。第二次起增量正常生效。**这是 by design**,不要为压代码删 legacy 兼容分支。

### 3.5 search.py CLI 参数变更

```bash
# v0.1
python scripts/search.py --scene 01 --terms "关键词"

# v0.2
python scripts/search.py --scope projects --terms "关键词"            # scope 替代 scene
python scripts/search.py --scope all --terms "关键词"                 # 跨 P+A+R 扫
python scripts/search.py --project 智慧城市可视化平台 --terms "关键词"  # 限定单项目(新增)
```

## 4. 已知问题与限制

### 4.1 v0.2.0 已知限制(release notes 摘录)

- **vsdx 正向路径未实证**:本机 LibreOffice 未装,vsdx 转 PDF 路径只验降级(`failed_no_libreoffice` 永久 stub)。装 LibreOffice 后可启用,**v0.2.1 计划回归**。
- **ODF (.odt/.ods/.odp) 入库走 stub 降级**:markitdown 0.1.5 不带 ODF converter,走 G15 永久 stub + `odf_status: failed_markitdown_no_odf_converter`。需正文检索请先用 LibreOffice 转 .docx 后再入库。
- **行为识别在 3+ 触发词混合场景靠 LLM 上下文推断**:CLAUDE.md §2.0 优先级规则只显式覆盖双叠加,三叠加(如"上次某客户那个项目里哪些章节对比过 X 和 Y")靠 LLM 推断"指向词最强者锁定"。欢迎 issue 反馈具体误判 case;累计 ≥ 2 误判触发补规则。

### 4.2 迁移期边界(常见踩坑)

- **LibreOffice 不可用时 vsdx 走永久 stub**(非 fail);如果你的 v0.1 corpus 有 `.vsdx` 文件,v0.2 入库后只会有 stub,正文不可检索 → 装 LibreOffice 重跑 / 或先用 LibreOffice 转 PDF 后入库
- **AI 语义路由首次跑可能 1-2 个文件归类不理想**:这是 by design 的 trade-off(AI 看子目录名判断,不可避免有边界 case)。**人工 mv 即可**;后续在 `path_map.yaml` 的 `explicit_mappings` 字段加该路径偏好,后续 ingest 直接命中
- **v0.5 增量机制首次跑全量重入**:见 §3.4。等它跑完即可,**不要中断**

## 5. 回滚

如果迁移中出问题,回滚到 v0.1.0:

```bash
# 方案 A:git 回滚(tag 可用时)
git checkout v0.1.0-pre-v02-migration   # 你在步骤 2.1 打的 tag
git reset --hard v0.1.0

# 方案 B:文件副本回滚
rm -rf agentic-kb-lite
mv agentic-kb-lite.backup-YYYYMMDD agentic-kb-lite
```
