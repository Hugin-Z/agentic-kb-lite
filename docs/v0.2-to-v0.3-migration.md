# v0.2 → v0.3 迁移指南

> v0.3 主题是 **tier 5 类分层 + `.shelved/` 子目录 + `search.py --deep` 三件套**。
> 设计目标:**材料不丢 + 默认检索干净**。
> v0.3 **完全向后兼容 v0.2**(无 plan_schema_version 的旧 plan + v0.2 已入库材料行为不变)。

---

## 1. 重大变更

| 维度 | v0.2.3 | v0.3.0 |
|---|---|---|
| **tier 分层** | 无 | 5 类:**canonical / normal / working / versions / assets**(详 CLAUDE.md §6 Step E) |
| **物理子目录** | 项目内 5 子目录(`01-方案 / 02-章节 / 03-纪要 / 04-调研 / 05-附图`)+ `99-其他` | 上述 + **`.shelved/{working,versions,assets}/`** 在 projects + areas + resources 三 bucket 每个 subdir 引入 |
| **search.py 默认行为** | 默认排除 `.archive/**` | 默认排除 **`.shelved/**` + `.archive/**`** 两个 |
| **search.py 新 flag** | 无 | `--deep`:包含 `.shelved/.archive/` 全扫(加 `--hidden`,真扫隐藏目录) |
| **routing_plan.json schema** | 6 必填字段 | 上述 + `tier`(可选,但 `plan_schema_version: v0.3` 时必填)+ `family_key`(仅 `tier=versions` 时必填) |
| **frontmatter schema** | type / date / project / tags | 上述 + **`kb_tier / kb_default_search / family_key`** 3 字段(ingest 自动注入) |
| **校验层** | 5 Layer | 上述 + **Layer 6**(三层:必填判定 / 类型 + 非空 + 白名单 / family_key Windows 非法字符) |

---

## 2. 迁移步骤

### 2.1 升级 v0.3 后立即可用(零操作)

- v0.2 已入库材料:默认按 `tier=normal` 参与检索,**行为与 v0.2.3 完全一致**
- v0.2 routing_plan 重跑(无 `plan_schema_version`):自动注入 `kb_tier: normal` + `kb_default_search: true`,**不报错不警告**
- search.py 默认行为:`.shelved/` 子目录在 v0.2 corpus 内不存在 → 排除规则不影响命中

### 2.2 让 `.shelved/` 真正发挥噪声分离作用(推荐,但非必须)

跑 dry-run migration helper:

```bash
python scripts/migrate_v023_to_v030.py
```

→ 生成 `logs/v030_migration_candidates_<YYYYMMDD_HHMMSS>.md`
→ 人工审清单(打勾 / 删除 / 修改候选)
→ 手动 `mv` 选定文件到目标路径
→ 删除 `logs/ingest_log.jsonl` 里对应旧 `target_rel_path` 的记录(避免增量判定混乱)
→ 重跑 ingest 让新 target 重新登记 frontmatter

**v0.3.0 限制**:helper **只 dry-run 输出候选,不自动 mv**(自动 mv 留 v0.4+,见 §4 已知问题)。

### 2.3 新材料入库

让 AI 在 routing_plan 阶段填 `tier` 字段(CLAUDE.md §6 Step E 协议):

- v0.3 新 plan 顶层加 `"plan_schema_version": "v0.3"`,每个 item 必填 `tier`
- `tier=versions` 时必填 `family_key`(基线名 + 类型,如 `总体方案_docx`,**不可含 Windows 非法字符**)
- AI 按文件名 / 父目录 / 内容上下文综合判断 tier,模糊时优先 `normal`(保守)

### 2.4 检索时(用户视角)

- **默认问法**:`search.py --scope all --terms "..."` → 不扫 `.shelved/` 内容(干净)
- **追溯问法**(含"之前 / 历史 / 草稿 / 版本 / 旧 / 过程 / 脚本"等关键词)→ LLM 倾向加 `--deep`:

```bash
python scripts/search.py --scope all --terms "之前的 build 脚本" --deep
```

详 CLAUDE.md §5.6.4。

## 3. 不兼容点

**无强制不兼容**。v0.3 完全向后兼容 v0.2 routing_plan + v0.2 已入库材料。

跨版本运行 v0.2 routing_plan(无 `plan_schema_version`)在 v0.3 引擎下:

- 缺 `tier` 字段 → 默认 `normal`(走现有 5 子目录,行为不变)
- 缺 `family_key` → 仅 `tier=versions` 时强制非空;`tier=normal` 时允许缺
- 缺 `plan_schema_version` → 走 v0.2 兼容模式(Layer 6.1 必填判定不触发,tier 缺允许)

---

## 4. 已知问题

- **migration helper v0.3.0 仅 dry-run**,**不自动 mv**。自动 mv 留 v0.4+ 实现。
  - **理由**:mv 会破坏 `logs/ingest_log.jsonl` / `.md` 内兄弟引用 / `.assets/` 相对路径 / `frontmatter kb_tier` 等**五件套一致性**,复杂度等价于重做一次 ingest(详 docs/v0.3-plan.md §7.3 步骤 4.2)
- **tier 判定靠 AI 推断**,边界 case 可能误判(如文件名含 `build` 但实际是项目最终方案)。**反馈累计 ≥ 2 误判触发补 CLAUDE.md §6 Step E 规则**(沿用 v0.2.2 W-5-W1 跟踪机制)
- **v0.2 已入库材料默认 `normal`**,若实际是 working/versions/assets,**需用户主动跑 migration helper**(§2.2)
- `--deep` 时 rg 才扫隐藏目录(`.shelved/.archive/`):v0.3 阶段 4A 修(W-v0.3-阶段3-W1)— 阶段 3 加 `--deep` flag 时只移除 glob 排除,**没加 `--hidden`**,导致实际仍扫不到隐藏目录。已在 v0.3 阶段 4A 补 `--hidden`,Smoke [16/16] 断言加强(用命中文件数 + 路径含 `.shelved` 双判定)

---

## 5. 回滚

如需回滚到 v0.2.3:

```bash
git checkout v0.2.3
```

**注意**:

- v0.2.3 不识别 `.shelved/` 子目录,但 `.shelved/` 内文件**不会被破坏**(只是默认 search 排除规则差异:v0.2.3 没 `!.shelved/**` glob,默认就走 rg `--hidden=false` 跳过隐藏目录;v0.3 显式加 glob 双保险)
- v0.3 注入到 frontmatter 的 3 字段(`kb_tier / kb_default_search / family_key`)在 v0.2.3 ingest 重跑时**不会被识别**也**不会报错**(v0.2.3 ingest 用 setdefault,不破坏已有字段)
- v0.3 routing_plan `tier` 字段在 v0.2.3 ingest 下:`_validate_plan_item_paths` 没 Layer 6,tier 字段被忽略 → 全部走现有 5 子目录(不进 `.shelved/`),**功能上等价 normal**
