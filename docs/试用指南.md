# 轻量知识库 试用指南

> 本文档是首次试用者的核心入口。装机、推荐问题、边界说明、反馈渠道全在这里。
>
> 已读过本指南后,日常使用读 [README.md](../README.md) + [CLAUDE.md](../CLAUDE.md)。

---

## 这是什么

**解决什么**:在你过往项目素材(方案文档 / HTML 原型 / 招标章节 / 会议纪要 / 调研笔记)里**快速定位**信息,并给出**带文件路径和行号的引用答案**。

**怎么做**:仓库自带 ripgrep(全文扫描)+ Python 包装层(三态分流 / 命中聚合 / 引用渲染);LLM(Claude Code 会话或其他)整合命中片段输出答案,**所有结论必须带出处**。

**优势**:
- **轻量**:含全部依赖约 380 MB,纯本地,断网可用
- **快**:百份级素材秒级返回
- **可追溯**:每个结论可点开引用核对,**LLM 不能编造**
- **诚实降级**:扫描件 / 图形主导 PPT 等检索盲区,系统主动声明"读不到正文,请打开源文件",不强行猜

**不做什么**:不是 RAG / 不做向量检索 / 不做 OCR / 不是万能问答。

## 怎么装

### 方法 A:双击 `install.bat`(推荐,最简单)

1. 在仓库根目录双击 `install.bat`
2. 看到 `[6/6] Install complete` 即完成,首次约 2-5 分钟(取决于网速)
3. 进度英文提示(bat 文件全 ASCII,避开 Windows cmd 中文编码坑)

### 方法 B:右键 `install.ps1` 选 "用 PowerShell 运行"(中文进度)

1. 在仓库根目录右键 `install.ps1` → "Run with PowerShell"
2. 如果提示"执行策略"错误(脚本被禁止执行),两个解法:
   - 在 PS 窗口跑 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`,再重试
   - 改用方法 A(更简单)

### 装机失败的常见三种

| 现象 | 处理 |
|---|---|
| `[1/6] [FAIL] Python 版本不在 3.10-3.12 范围` | 装 Python 3.10 / 3.11 / 3.12,下载页 https://www.python.org/downloads/ ,装时勾选 "Add Python to PATH" |
| `[4/6] [WARN] 首次 pip install 失败,自动用清华镜像重试` | 自动重试,无需手工干预;若重试仍失败见下条 |
| `[4/6] [FAIL] pip install 重试仍失败` | 多为代理 / SSL 问题,按提示设置 HTTPS_PROXY 或升级 pip 后重跑 install |
| `[2/6] [FAIL] tools/rg.exe missing` | 仓库不完整,重新下载完整仓库或检查 zip 是否完全解压 |

## 怎么用(三步)

### 第 1 步:理解 corpus PARA 结构(v0.2 起)

corpus 分四层,由 AI 在 ingest 时自动语义路由:

| PARA 一级目录 | 放什么 | 典型场景 |
|---|---|---|
| `01-projects` | 在做的具体项目;内部 5 固定子目录(`01-方案 / 02-章节 / 03-纪要 / 04-调研 / 05-附图`)+ `99-其他` | "上次某客户那个项目怎么做的" |
| `02-areas` | 长期维护的责任领域(产品方案库 / 行业解决方案 / 投标章节模板 / 技术方法论) | "产品方案怎么写架构这章" |
| `03-resources` | 参考资料(国标行标 / 行业研究 / 竞品资料 / 培训与调研) | "国标里地块编码字段是什么" |
| `04-archives` | 已交付且不再用的老项目(默认不在 P+A+R 全扫 scope) | "之前那个老项目" |

**通常不需要改 `path_map.yaml`** — AI 自动判断。

仅当 AI 路由不理想时,在 `path_map.yaml` 的 `explicit_mappings` 字段加一条用户偏好兜底:

```yaml
explicit_mappings:
  - source: "C:/你的项目根目录/某合同包"
    target: "02-areas/合同档案/"
    reason: "目录含项目名但内容是合同,归 areas 更合适"
```

### Windows 路径约定(避免 MSYS /tmp 陷阱,v0.2 阶段 2 教训)

测试合成临时素材时,**用 Windows 绝对路径或 `%TEMP%\test_xxx\` 风格**,**不要用 `/tmp/...`**。

原因:MSYS bash 翻译 `argv` 但**不翻译** Python 源码字符串字面量。同一个 `/tmp/x` 在 bash 里是 `%TEMP%\x`,在 Python `Path('/tmp/x')` 里是 `C:\tmp\x`,两个不同位置。详见 [tests/v0.2-plan-progress.md](../tests/v0.2-plan-progress.md) W-v0.2-阶段2-W2。

### 第 2 步:首次入库(v0.2 起两步流程)

v0.2 ingest 分两步:**scan-only 扫源目录 → AI 产路由 plan → execute-plan 落地**。整个流程在 AI 编程助手对话层一气呵成:

```text
你对 Claude Code 说:"把 D:/我的项目资料 入库"

Claude Code 自动:
  1. Bash: python scripts/ingest.py scan-only D:/我的项目资料
     → logs/routing_request.json
  2. Read routing_request.json + path_map.yaml + CLAUDE.md §6
     → AI 产 routing_plan.json
     → 展示方案给你过目(不强制确认)
  3. Bash: python scripts/ingest.py execute-plan logs/routing_plan.json
     → 按 plan 执行迁移 + frontmatter 注入
  4. 报告结果
```

系统会自动:

- **AI 语义路由** → 整个项目目录归到 `01-projects/<项目名>/`,内部按内容分到 5 子目录;`标准/` 子目录脱钩到 `03-resources/国标行标/`(加项目前缀消歧)
- **frontmatter 注入** → 4 字段 type/date/project/tags 自动注入 .md / .stub.md
- **G14/G15/G16/G18 分流** → binary 转 .md 入库,扫描类 / 结构性稀薄类走 stub
- **嵌入图 / 嵌入表 / vsdx / odf 兼容** → 详见 [README.md §5.1](../README.md)

### 第 3 步:检索(v0.2 双轴 + --project)

```powershell
python scripts/search.py --scope <projects|areas|resources|archives|all> --terms "关键词1,关键词2"
python scripts/search.py --project <项目名> --terms "关键词1"     # 限定单项目
```

多个关键词用逗号分隔,系统按 OR 命中。常用参数:

| 参数 | 含义 |
|---|---|
| `--scope projects/areas/resources/archives/all` | PARA scope 限定(默认 projects;all=P+A+R,不含 archives) |
| `--project <名>` | 限定到 `corpus/01-projects/<名>/`(scope 自动隐含 projects;v0.2 新增) |
| `--terms "词1,词2"` | 检索词,逗号分隔 |
| `--max-files 8` | 命中文件数上限(默认 8) |
| `--no-stub` | 只搜正文,不搜 stub |
| `--regex` | 正则模式(默认 fixed-strings,括号 / 星号 / 方括号等检索词安全) |

### scope × behavior 双轴(用户不用选,AI 自动)

AI 在轮 1 状态段同时识别:

- **scope**(扫哪个目录):projects / areas / resources / 跨corpus,由 CLAUDE.md 第 5 节按问法关键词路由
- **行为**(怎么整合答案):单点定位 / 盘点 / 决策溯源 / 模糊探索,由 CLAUDE.md 第 2.0 节按问法关键词识别

**用户不被问任何选择题**,两轴都自动。详见 [CLAUDE.md §2.0 + §5](../CLAUDE.md)。

## 怎么读输出

输出有三个区,对应文件状态:

### 一、正文命中

`.md` / `.html` / `.txt` 等可检索正文文件。带行号引用,可点开核对。

### 二、stub 命中(分两类)

- **配套元数据**(三件共存,正文在同目录 .md):stub 仅作元数据索引,**正文已转 .md 入库**,LLM 优先读 .md 给答案
- **正文未入库**(扫描件 / 结构性稀薄):**触发 stub 禁令**,LLM 不会推断正文,只指引你打开源文件路径

### 三、未命中检索词

逐词显示命中分布。全 0 命中时给出回退建议(同义词扩展 / 收窄检索词)。

### 注:输出里有些"LLM 必读"的段是什么?

search.py 的输出本质是给 LLM(Claude Code 会话)读的"结构化报告",所以你会看到 `## ⚠ stub 命中处理规则(LLM 必读)`、"步骤 6 回退判断"、"严禁编造" 这种段——那是给 AI 看的接口契约,人类用户忽略即可。

实际你只需要关注三行:

- 头部 `**命中文件**: X` —— 命中了几份(X=0 时直接看下面第三条)
- `## 一、正文命中` / `## 二、stub 命中` —— 真正的检索结果,带文件路径 + 行号,可直接点开核对
- 0 命中时,看 `## 三、未命中检索词` 的回退建议(同义词扩展 / 检索词收窄)

其他 "LLM 必读" 段落不影响你判断答案对错,跳过即可。

## 推荐试用问题

> 以下问题按"系统能力维度"设计,是通用模板。试用者 ingest 自己的素材后,把检索词换成你自己素材里的真实关键词跑。每题标注**预期**和**看点**——看点是想验证的系统能力维度。

### 第一轮验证的关键

**先用你确定资料里一定存在的关键词测试**,比如:

- 项目名(你刚 ingest 的那个项目的具体名字)
- 客户名 / 对方公司名
- 你记得的具体功能名 / 模块名
- 某次会议的具体日期

不要用"AI"、"系统"、"管理"这类宽泛词——可能命中太多 noise,也可能因为
你的文档里实际用的是别的表述(比如文档写"平台"但你搜"系统")而 0 命中。

0 命中不代表系统坏了,常见原因是:① 关键词没在文档里出现;② 你的关键词
和文档实际用词不一致(同义词问题)。两种情况都可以换一组关键词重试。

### 能直接回答(基于已入库的文档正文)

**Q1. 在历史方案里找某个功能模块的实现细节**
- 命令:`.venv\Scripts\python.exe scripts/search.py --scene 01 --terms "<功能名>,<同义词1>,<同义词2>"`
- 预期:HTML / .md 正文多份命中,直接给答案 + 文件路径 + 行号
- 看点:**带行号引用 + 跨版本一致性证据**——若有多版本素材,系统会显示功能在哪几版稳定存在

**Q2. 在投标章节里找某类技术应答的写法**
- 命令:`.venv\Scripts\python.exe scripts/search.py --scene 02 --terms "<技术名>,<章节关键词>"`
- 预期:历史投标章节的 .docx.md 命中,LLM 拿到原文 + 可参考的章节结构
- 看点:**docx → markdown pipeline**——投标 docx 自动转 .md 入库后,正文片段可直接复用

**Q3. 在个人记忆里追溯某次会议或讨论的具体结论**
- 命令:`.venv\Scripts\python.exe scripts/search.py --scene 04 --terms "<日期>,<对方>,<主题>"`
- 预期:纪要 .docx.md 命中,LLM 直接给会议讨论结论 + 行号(纪要 docx 已转 markdown 时)
- 看点:**关键词命中精度**——日期 + 与会人 + 主题三维检索词通常能精准命中,避免噪声

### 能定位文件(系统找到了文件但不能读正文)

**Q4. 问某份扫描类 PDF 的具体内容**
- 命令:`.venv\Scripts\python.exe scripts/search.py --scene 01 --terms "<PDF 文件名关键词>"`
- 预期:扫描 PDF stub 命中,LLM 不编正文,只指引"该 PDF 是扫描件,文本层为空,请打开源文件自己看"
- 看点:**诚实降级**——遇到扫描件不强行编造

**Q5. 问某次会议的具体讨论内容,该纪要 docx 仍处于 stub 状态**
- 命令:`.venv\Scripts\python.exe scripts/search.py --scene 04 --terms "<日期>,<对方>"`
- 预期:纪要 stub 命中,LLM 给文件清单 + 文件名层关键词,不推断会议内容
- 看点:**stub 元数据索引价值**——文件名层的"日期 / 与会人 / 主题词"已可命中,正文不可读时系统明示

### 边界问题(故意问系统不擅长的,看降级行为)

**Q6. 问某份图为主的 PPT(架构图 / 流程图 / 拓扑图)的具体内容**
- 命令:`.venv\Scripts\python.exe scripts/search.py --scene 01 --terms "<PPT 文件名关键词>"`
- 预期:图为主 PPT 文本层稀薄,ingest 时触发结构性稀薄判定 → 永久 stub 化;LLM 明示"图形为主,无法读取正文,请打开源 PPT"
- 看点:**字符密度判定**——形状 / 连线 / 位置等图形关系超出 ripgrep 能力,系统主动声明而不假装能答

**Q7. 问跨项目某个技术决策细节(比如"我们之前用过什么数据库")**
- 命令:`.venv\Scripts\python.exe scripts/search.py --scene 03 --terms "<项目名>,数据库,选型"` 或 `--scene all`
- 预期:若有 ADR / 决策记录素材入库,LLM 直接给答案 + 行号;若只有纪要 stub,LLM 严禁补全数据库名(即使自身知识里"该公司常用某数据库"也禁止),只指引"请打开源 docx 自己看"
- 看点:**stub 禁令铁律**——即使 LLM 自身知识里有相关推断,也不能写进答案;**只可信来自 corpus 命中的内容**

## 不解决什么(已知边界)

- **扫描 PDF / 带覆层的 PDF**:不能读正文,只能定位文件
- **图形关系主导 PPT**(架构图 / 流程图 / 拓扑图):不能 ripgrep 命中,只能命中文字标签
- **场景 2(投标章节复用)/ 场景 3(技术决策溯源)**:建议优先验证场景 1(历史方案)和场景 4(个人记忆);场景 2 和 3 的命中率取决于你放入的真实素材质量。
- **不是 RAG 工程**:不需要向量库 / embedding 模型 / rerank 模型(降低部署门槛,代价:意外同义词的漏召率比成熟 RAG 高)
- **不做 OCR**:扫描件维持 stub 状态,不强行识别
- **不做自动版本族归档**:同一项目多版本(如 v1 / v2 / ... / v10)需要人工判定哪些归档

## 反馈

试用中遇到任何问题 —— 装不上 / 跑出错 / 答得不准 / 想要新功能 —— 请联系维护者。

期望反馈维度:
- **答案对不对**(可点引用核对)
- **答得有没有用**(对你解决问题的实际帮助)
- **降级是否诚实**(找不到时是说"未找到"还是编造)
- **响应速度 / 装机门槛 / 操作直觉性**
