# 格式支持边界

> 本文档说明各类文件格式在 ingest 时的处置方式与已知边界(从 README §5.1 外移)。
> 总原则:**能转正文的转正文,转不了的诚实降级为 stub / vision,绝不静默丢文件、绝不推断未入库正文**。

---

## 1. 常规路径(无需额外处理)

| 类型 | 处置 |
|---|---|
| `.md` / `.txt` 等文本 | 直接入库(G16 三件共存) |
| `.docx` / `.pptx` / `.pdf` / `.xlsx` | markitdown 转 `.md` 入库;v0.4 起 G16 binary 转出的 `.md` 过一道 baseline recipe 字面清理 |
| `.docx` 嵌入图 | ingest 自动 zipfile 解嵌入图(三闸过滤 + zip-slip 防御),vision 转写**注入原 `.md` 末尾 `## 嵌入图 vision 转写` 段**,不单建 `.vision.md` |
| `.docx` 嵌入表 | python-docx 抽取补段 |
| `.pptx`(图为主,触发 G18) | ingest 自动解 `ppt/media/*` 嵌入图到 `<pptx名>.assets/`,vision 转写完即删该目录;**不需要用户手动导出 PDF/PNG** |
| 扫描类 PDF(markitdown 0 字符,G15) | 走 vision 路径 A;需前置 PDF→PNG 工具(推荐 poppler,`winget install poppler`) |
| 图像 `.png/.jpg/.jpeg/.gif/.bmp/.webp/.tif/.tiff` | vision 路径 A,产出 `.vision.md` |
| 视频 `.mp4/.mov/.avi/.mkv/...` | vision 路径 B:ffmpeg scene 抽帧 + 双层密度算法 → 单份 `.vision.md`(叙事段 + 带时间戳的帧明细) |

---

## 2. 需要用户先做一步的格式

### xmind(思维导图)

**不直接支持**。请先在 XMind 桌面端**导出为 PNG 或 PDF**,再 ingest 导出文件。导出的 PNG 会走 vision 路径 A(图为主文件)转写,实现内容检索。

### shp(GIS 空间数据)

`.shp/.shx/.dbf/.prj` 等空间数据文件**不在本仓库检索范围**(落 stub 标记文件存在,不参与正文检索)。如果需要"项目用过什么投影 / 字段名"等元数据级检索,请用 GIS 工具(QGIS / ArcGIS)导出 `.prj` 投影信息和 `.dbf` 字段名为 `.txt`,再 ingest。

未来若加专用解析器(GDAL 读 `.shp` / `.dbf`),重跑 ingest 即可重入正文。

### `.ppt`(老格式)

Claude 不支持直接读取。用户先手动导出为 PDF / PNG 序列,再走对应路径。

---

## 3. 降级路径(不阻塞 ingest,装齐依赖后重跑自动恢复)

### vsdx(Visio)

走 **LibreOffice headless 转 PDF** 后接 binary 路径。**LibreOffice 不可用时永久 stub 标 `failed_no_libreoffice`**(降级,不阻塞)。安装 LibreOffice 后重跑 ingest 自动转换。

> **已知限制**:v0.2.0 release 时本机未装 LibreOffice,**正向路径未实证**,只验证了降级分支。

### odf(OpenDocument)

`.odt/.ods/.odp` 经 markitdown 处理。**markitdown 0.1.5 不带 ODF converter,实际走 G15 永久 stub + `odf_status: failed_markitdown_no_odf_converter` 标记**。

需正文检索请先用 LibreOffice 转 `.docx` 后再入库(已有完整 docx G16 路径)。markitdown 后续版本支持 ODF 时自动生效,无需改代码。

### markitdown 转换失败 / 未知扩展名(v0.2.3 起)

不再直接报错终止,改为**源文件 cp + stub 二件共存**(`MARKITDOWN_FAILED_STUB` / `UNSUPPORTED_COPY_STUB`)。装齐依赖后重跑 ingest 自动重入正文。

### 扫描 PDF 缺 PDF→PNG 工具

自动降级到 L3 stub 兜底,`vision_status` 字段记 `failed_no_pdf_converter`。装 poppler 后重跑即可。

### 视频缺 ffmpeg

视频整批跳过(`vision_status: skipped_no_ffmpeg`),**图像 / PDF 的 vision 路径 A 不受影响**(软依赖降级)。

---

## 4. 明确不做的事

- **不解析 PPT / 视频的非视觉部分** —— 以 AI 编程助手内置 vision 转写文本入库
- **不做语义级清洗 / 字段抽取 / 表头语义识别 / 跨 3+ 表合并** —— v0.4 recipe 是 experimental baseline 骨架,真实语料调参由使用者完成
- **不从 stub 推断正文** —— stub 只是元数据索引;答案必须标注"原文件未入库正文,建议打开原文件"
- **不基于 `.vision.md` 编造图中未明文出现的细节** —— 详见 [CLAUDE.md §3.5 vision 告知规则与禁令](../CLAUDE.md)
